Privacy Policy — Sunmini (볕조각)

Effective date: 2026-09-28 App: Sunmini / 볕조각 / サンミニ / 小太陽 (package app.sunmini.film) Developer: Byeotjogak

English · 한국어

English

Summary

Sunmini is a film camera app that works on your device. It does not collect, store on a server, or share any personal data. There are no accounts, no ads, no advertising ID, and no third-party analytics or crash-reporting services. Your photos never leave your device unless you choose to share them yourself. The only thing the app downloads on its own is a small list of films (see "Film catalog download" below), and that request contains no personal data. The app sends two things: once a day, anonymous counts of how each film was used, with no identifier, which you can turn off in Settings (see "Anonymous usage statistics"); and, only if you redeem a gift code, that code and a random install id, nothing that identifies you (see "Gift codes").

Data we collect

No personal data. The app does not collect your name, e-mail, account, contacts, device identifiers, advertising ID, location or crash reports, and it does not send your photos anywhere. It sends only:

  • anonymous daily film usage statistics: counts per film and day, with no identifier (you can turn this off; see "Anonymous usage statistics"), and
  • a gift code you choose to redeem, with a random install id (see "Gift codes").

On-device processing and storage

  • Photos you take or import are developed (colour, grain, date stamp, border, trial mark) entirely on your device.
  • Developed photos are saved to your device's photo library, in Pictures/Sunmini.
  • The original, undeveloped image of each shot is kept in the app's private storage so you can develop it again later (for example with another film, or without the trial mark after a purchase). Other apps cannot read this storage.
  • Your settings, the films you own, the count of trial shots used and the downloaded film catalog are stored only on the device.
  • The film usage counts of the days not sent yet (see "Anonymous usage statistics") are kept in the app's private storage until they are sent, for at most 7 days. They are not backed up.
  • Redeemed gift codes (the signed gift, the random install id and the list of cancelled codes) are kept in one small file. It is the only app data included in Android's own backup (Auto Backup to your Google account, and device-to- device transfer), so a gift survives a reinstall or a new phone. Nothing else is backed up: no photos, originals, settings, trial counters or purchases (Google Play restores purchases itself).
  • Deleting a photo in the app removes it from the app and from Pictures/Sunmini. Uninstalling the app removes all app-private data (originals, trial counters, settings, the cached catalog, unsent usage counts, gifts). Photos already saved to your photo library stay there until you delete them; a backed-up gift file stays in your Google account backup until Android replaces or deletes it.

Film catalog download

To add new films and update film looks, names and order without an app update, the app downloads a small film catalog: a JSON file, its digital signature, film profiles (JSON) and film character images. The files are public static files hosted on Cloudflare (https://sunmini-catalog.sunmini.workers.dev/v1/), with an identical copy on GitHub Pages (https://minchang-k.github.io/sunmini-catalog/v1/) that is asked only when Cloudflare cannot be reached. When you open the app it checks for a new catalog, at most once every 15 minutes (usually a tiny "not changed" answer), and uses a new one only if its signature is valid, from the next start; otherwise it keeps the films it already has. Shooting and developing work without it.

The request contains no personal data: no account, no identifier, no photos, no settings and no information about your purchases. Like any web request, it reveals your IP address to the host; the app sends the fixed User-Agent Sunmini (no device model or Android version). We do not log these requests; we see only aggregate daily request counts. Cloudflare and GitHub, as hosts, may keep request logs under the Cloudflare Privacy Policy and the GitHub Privacy Statement. Films shown first in some countries are chosen on your device from your device's language/region setting; your country is not sent. (The only place where our server uses a country is the anonymous usage statistics below, where it comes from Cloudflare, not from your device.)

Gift codes

The developer can give films away with one-time gift codes (SUN-XXXX-XXXX-XXXX), shared as a code or a link. When you redeem one (Settings → Redeem code, and you confirm), the app sends to our server (https://sunmini-api.sunmini.workers.dev/, a Cloudflare Worker with a Cloudflare D1 database) only:

  • the code, and
  • a random install id: 128 random bits made by the app once, not derived from your device, account or phone number.

Our server stores that install id and the time with the redeemed code, so each code can be used only once (and the same install can redeem it again after a reinstall). It is not linked to your name, e-mail, Google account or purchases, and it is used for nothing else. The server also counts attempts per IP address for a short time to stop code guessing; IP addresses are not stored with the code. The server answers with a signed gift that the app checks on the device and keeps in the gift file described above; using a gifted film never contacts the server again. To have a redemption record deleted, contact us with the code.

Anonymous usage statistics

To learn which films people actually use, so that we can decide the order of the film shelf and which films to keep, improve or retire, the app counts on your device how each film is used each day and sends these counts to our server (https://sunmini-api.sunmini.workers.dev/, the same Cloudflare Worker and D1 database as for gift codes).

  • What is sent, for each film you used that day: how many times it was picked, shots taken, pictures saved, pictures shared, trial shots taken, whether its last trial shot was used, how often its purchase sheet was opened, purchases, and gift-code unlocks. With these counts: the app version, the film catalog version, the Android major version (for example 16), the kind of device (phone, foldable or tablet), whether the app is a test build or from Google Play, and a random batch id that is new every day and is used only to notice the same upload arriving twice.
  • When: once a day, the next time you open the app, it sends the counts of each finished day in one small request (at most 3 KB; a very busy day may take a few). If that fails (for example offline), it tries again at a later app open; counts older than 7 days that could not be sent are deleted on the phone.
  • What is not sent: no photos, no install id or user id, no account, name or e-mail, no Android ID or advertising ID, no location, no settings and no list of your pictures. Nothing links one day's counts to another day or to you.
  • On the server: like any web request, the upload reveals your IP address to Cloudflare. Our server takes only the country code that Cloudflare derives from it (for example KR) and adds your counts to daily totals per film, country, app version, catalog version and channel (test or Google Play). The upload itself and your IP address are not stored: a salted hash of the IP address is kept for at most one hour to limit abuse, and the random batch id for up to 8 days to drop duplicates. The daily totals are kept to compare films over time; because they hold no identifier, they cannot be linked to you or deleted per person.
  • Your choice: the switch Settings → "Send anonymous film usage statistics" is on by default. When you turn it off, the app stops counting and sending, and deletes the counts it has not sent yet.

Permissions and why

Permission Why
Camera (CAMERA) To take photos. Asked at first launch. If you decline, you can still import and develop existing photos.
Internet (INTERNET) To download the film catalog described above, to send the anonymous usage statistics (unless you turn them off), to redeem a gift code you enter, and for Google Play Billing.
Google Play Billing (com.android.vending.BILLING) To buy films as in-app purchases through Google Play.
Network state (ACCESS_NETWORK_STATE) Declared by the Google Play Billing Library the app includes, not used by the app's own code.

The app requests no storage, media or location permission. To import photos the app uses the Android system photo picker, which shares only the photos you pick.

Purchases (Google Play Billing)

Four films are free. The other films can be bought one by one as one-time in-app purchases; each paid film can be tried for 3 shots first. Payments are handled entirely by Google Play; we never see your payment details, name or e-mail address. The app receives only the purchase state (which films you own) from Google Play on your device, so it can unlock them. Purchases never pass through our server; the anonymous usage statistics only count how many times each film was bought that day, with no purchase token, order number, price or identifier. Purchases are processed by Google under the Google Privacy Policy.

Children

The app is suitable for all ages. Because it collects no personal data from anyone, it collects none from children (a redeemed gift code is stored only with a random install id, and the usage statistics are anonymous daily totals).

Changes to this policy

If this policy changes, the updated version will be published at this address with a new effective date. If the app ever starts collecting more data, this policy will say so before that version is released.

선물 코드

개발자는 한 번만 쓸 수 있는 선물 코드(SUN-XXXX-XXXX-XXXX)로 필름을 선물할 수 있으며, 코드나 링크로 전달됩니다. 사용자가 코드를 등록하면(설정 → 코드 등록, 사용자가 직접 확인) 앱은 개발자의 서버 (https://sunmini-api.sunmini.workers.dev/, Cloudflare Worker와 Cloudflare D1 데이터베이스)로 다음만 보냅니다.

  • 코드
  • 무작위 설치 ID: 앱이 한 번 만든 128비트 난수로, 기기, 계정, 전화번호에서 만든 값이 아닙니다.

서버는 각 코드를 한 번만 쓸 수 있도록(같은 설치는 재설치 후 다시 등록할 수 있도록) 등록된 코드와 함께 이 설치 ID와 등록 시각을 저장합니다. 이 정보는 이름, 이메일, Google 계정, 구매 정보와 연결되지 않으며 다른 용도로 쓰지 않습니다. 코드 추측을 막기 위해 서버는 IP 주소별 시도 횟수를 잠시 세지만, IP 주소를 코드와 함께 저장하지 않습니다. 서버는 서명된 선물을 돌려주고, 앱은 이를 기기에서 확인해 위의 선물 파일에 보관합니다. 선물받은 필름을 쓸 때는 서버에 다시 연결하지 않습니다. 등록 기록의 삭제를 원하면 코드와 함께 문의해 주세요.

익명 사용 통계

사람들이 실제로 어떤 필름을 쓰는지 알고, 이를 바탕으로 필름 진열 순서와 남기거나 다듬거나 정리할 필름을 정하기 위해, 앱은 필름별로 하루 동안 얼마나 쓰였는지를 기기 안에서 세어 개발자의 서버(https://sunmini-api.sunmini.workers.dev/, 선물 코드와 같은 Cloudflare Worker와 D1 데이터베이스)로 보냅니다.

  • 보내는 정보: 그날 쓴 필름마다 고른 횟수, 촬영 수, 저장한 사진 수, 공유한 사진 수, 체험 촬영 수, 마지막 체험 컷을 썼는지, 구매 화면을 연 횟수, 구매 수, 선물 코드로 열린 횟수. 함께 보내는 것은 앱 버전, 필름 목록 버전, Android 주 버전(예: 16), 기기 종류(휴대폰, 폴더블, 태블릿), 테스트 빌드인지 Google Play 빌드인지, 그리고 같은 전송이 두 번 도착했는지 알아보는 데만 쓰는, 매일 새로 만드는 무작위 묶음 ID입니다.
  • 보내는 때: 하루 한 번, 앱을 다음에 열 때 지난 날의 횟수를 작은 요청 하나(최대 3KB, 아주 많이 쓴 날은 몇 개)로 보냅니다. 보내지 못하면(예: 오프라인) 나중에 앱을 열 때 다시 시도하며, 7일이 지나도록 보내지 못한 횟수는 휴대폰에서 지웁니다.
  • 보내지 않는 정보: 사진, 설치 ID나 사용자 ID, 계정·이름·이메일, Android ID나 광고 ID, 위치, 설정, 사진 목록은 보내지 않습니다. 어느 날의 횟수를 다른 날이나 사용자와 연결할 수 있는 정보는 없습니다.
  • 서버에서: 모든 웹 요청과 마찬가지로 전송 시 IP 주소가 Cloudflare에 전달됩니다. 서버는 Cloudflare가 이 주소에서 알아낸 국가 코드(예: KR)만 사용해, 받은 횟수를 필름·국가·앱 버전·필름 목록 버전·채널(테스트 또는 Google Play)별 하루 합계에 더합니다. 받은 요청 자체와 IP 주소는 저장하지 않습니다. 남용을 막기 위해 IP 주소의 솔트 해시를 최대 1시간, 중복을 거르기 위해 무작위 묶음 ID를 최대 8일 보관할 뿐입니다. 하루 합계는 필름을 기간별로 비교하려고 보관하며, 식별자가 없어 사용자와 연결하거나 사람별로 지울 수 없습니다.
  • 선택: 설정 → "익명 필름 사용 통계 보내기"는 기본으로 켜져 있습니다. 끄면 앱은 횟수를 세거나 보내지 않고, 아직 보내지 않은 횟수도 지웁니다.
